# 0001. 承認しきい値をコードに置く

- 状態: 採用
- 日付: 2026-05-18

## 背景

承認段数を決める金額のしきい値（3万円、30万円）と、領収書が必要になる金額（3千円）を
どこに持つかを決める必要があった。候補は次の2つ。

1. `app/config.py` に定数として置く
2. `settings` テーブルを作り、管理画面から変更できるようにする

管理部門からは「経理規程が変わったときに自分たちで変えたい」という要望が出ていた。

## 決定

コードに置く（案1）。

## 理由

- しきい値が変わると、過去に承認された申請の妥当性の説明が変わる。いつ何が変わったかを
  追えることが監査対応で効く。コードならコミットが履歴そのものになるが、DB の値を
  書き換える方式だと変更履歴を別途作り込むことになる。
- しきい値は経理規程の改定に連動するので、変更の頻度は年に1回あるかどうか。画面から
  変えられる必要はない。
- 段数は `required_steps()` の単体テストで固定できる。DB から読むと、テストのたびに
  値を用意する必要が出て、境界値のテストが書きにくくなる。

## 結果

- しきい値の変更にはデプロイが要る。管理部門からの依頼を受けて開発が変更する運用にした。
- `app/config.py` が経理規程との対応表になっている。規程の条番号はコメントに書かない
  （規程側の改番で嘘になるため）。
