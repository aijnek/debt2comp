# 0002. 承認待ちの通知はリクエストの中で同期的に送る

- 状態: 採用
- 日付: 2026-06-02

## 背景

申請が誰の手元で止まっているか分からず滞留する問題への対応として、次の承認者へ通知を
出すことにした。送信の方式として次を検討した。

1. 申請・承認のリクエストの中で、同じトランザクションで通知行を作る
2. ジョブキューに積み、ワーカーが非同期に送る

## 決定

同期送信（案1）。通知は `notifications` テーブルへの INSERT であり、状態変更と同じ
トランザクションに入れる。

## 理由

- 通知先はアプリ内の受信箱であって、外部サービスへの送信ではない。ネットワーク越しの
  失敗もリトライも存在しないので、非同期にする理由がほとんどない。
- 「承認したのに次の人に通知が飛んでいない」状態を作りたくない。同一トランザクション
  なら、状態変更と通知は同時に成立するか同時に無かったことになる。
- ワーカーのプロセスを増やすと、社内の小さなアプリに対して運用の面倒が釣り合わない。

## 結果

- メール送信を足すときは、この決定を見直す必要がある。外部送信はトランザクションの中に
  入れられないので、そのときは通知行の作成（同期）と送信（非同期）を分けることになる。
- 通知の宛先の決め方は `app/services/notification.py` に閉じている。
