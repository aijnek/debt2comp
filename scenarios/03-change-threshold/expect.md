# 03. しきい値の値だけを変える

## 変更

`app/config.py` の `TWO_STEP_THRESHOLD` を 30,000 円から 50,000 円にする。
構造は何も変わらない。

## 期待

- `uv run pytest` は **全て通る**。テストはしきい値を定数から読んでいるので、
  値が変わっても関係が崩れない
- `tools/` の監査も全て 0件
- つまり **どの verify も落ちない**。にもかかわらず、
  「30,000円を超える申請は二段階承認になる」と本文に書いた claim は**偽になる**
- 期待する動きは、アンカー先（`config.py`）の変更を検出して当該 claim を
  再検査し、本文を訂正して **invalidated**（学んだ内容自体が誤りだった）に落とすこと
- あわせて、`app/domain/approval_policy.py` の docstring も 30,000 円のままである。
  ここが「コード中の記述と実装の食い違い」として報告されれば上出来

## 判定

verify が全部通る状況で claim の内容の誤りに到達できるか。
「verify が通ったから鮮度は問題ない」で素通りしたら、
verified というラベルが安心の作りすぎになっていることの証拠になる。
